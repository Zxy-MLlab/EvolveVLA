## 1. 目标与历史结论

**Batch 64 开训时快照（北京时间 2026-10-15 约 19:27）：**9 个 batch、576 次采样的混合预检通过，720 个训练前验证锚点完成；`gen1_replay_expanded_lora_b64_20261015/metrics.jsonl` 当时已记录至少 6 次参数更新，第 6 步 loss 为 0.004021，梯度与 loss 均有限。训练 PID 690854、自动导出/rollout 队列 PID 688402；当时尚未到 1000 步，故没有本轮成功率结果。停止的 batch 32 初始化没有产生训练更新或 checkpoint。

目标是利用本地采集数据和官方 RoboTwin 数据微调 π0.5，提高鼠标垫（`place_mouse_pad`）与挂杯（`hanging_mug`）任务的实际成功率，同时尽量避免其他任务退化。

**目前尚未得到稳定、可重复的成功率提升。**训练损失和离线动作误差下降，但闭环收益不稳定，部分实验出现鼠标垫改善、挂杯退化。一次 6000 步 LoRA 评估有明显的样本内提升，但还不足以宣称问题已解决。

## 2. 这几天做了哪些尝试

- **初期微调与诊断：**完成 2000 次更新的 pilot（checkpoint 编号 1999），随后检查数据加载、动作目标、归一化、模型输出和轨迹执行。
- **增强与覆盖实验：**尝试指令增强、原生训练流程及 coverage 版本，并对候选 checkpoint 做离线选模和实际 rollout。
- **18 任务全参训练：**batch size 8，完成 24000 步，使用任务均衡采样。
- **关键阶段加权训练：**提高专家轨迹中部分操作阶段的采样权重，batch size 8，完成另一轮 24000 步。
- **官方数据混合＋LoRA：**混入对应 18 个任务的官方数据，沿用初始化 checkpoint 的 norm stats，batch size 提高到 32，先完成 6000 步，再续训。续训日志到 20942 步；已有 18000 步 checkpoint 的 rollout，不能称这轮已完成 24000 步。
- **扩充采集：**鼠标垫、挂杯各达到 1000 条通过采集审计的轨迹；每个任务包含原有 50 条和新增 950 条。
- **动作分布检查：**按任务比较本地与官方的关节位置、夹爪值、单步动作幅度及左右臂活动比例。

## 4. 实际 rollout 结果

以下均为两个任务各 **10 次有效配对**的 Clean 闭环诊断。单元格表示“原模型 → 微调模型”的成功次数；总成功率分母均为 20。

| 实验／评估轮次 | 鼠标垫成功次数 /10 | 挂杯成功次数 /10 | 两任务总成功率 |
|---|---:|---:|---:|
| 原生增强，2000 步 | 1 → 1 | 1 → 0 | 10% → 5% |
| Coverage，2000 步，确认 1 | 1 → 2 | 3 → 3 | 20% → 25% |
| 同一 Coverage 模型，确认 2 | 0 → 1 | 4 → 0 | 20% → 5% |
| 18 任务均衡全参，24000 步 | 0 → 2 | 3 → 1 | 15% → 15% |
| 关键阶段加权，24000 步，确认 1 | 1 → 2 | 3 → 3 | 20% → 25% |
| 同一阶段加权模型，确认 2 | 1 → 4 | 1 → 0 | 10% → 20% |
| 官方混合＋LoRA，6000 步 | 0 → 4 | 1 → 2 | 5% → 30% |
| 官方混合＋LoRA，18000 步 | 0 → 2 | 2 → 0 | 10% → 10% |

这些是小样本、固定指令和策略随机数的配对诊断，并非官方 50 任务完整榜单。只统计有效配对，专家拒绝等未配对尝试不计入这 10 次；各轮有效 seed 集合可能不同。因此应优先比较同一行的微调前后，不能把不同轮次的百分比直接当作严格的 checkpoint 排名，也不能与官方 Clean 约 82.7% 直接比较。

## 5. 已发现的问题

1. **离线误差与闭环成功率不一致。**已有失败轨迹显示：鼠标垫常在抓起后最终位置不达标；挂杯的差异出现在靠近杯架、释放阶段。尚未证明单一根因。
2. **动作格式对齐，但分布并非完全相同。**挂杯单步关节变化幅度相对官方约 −2.9%，鼠标垫约 +2.0%；鼠标垫左臂主导轨迹占比为本地 48.8%、官方 38%。这可能来自场景与抽样差异，不能直接视作数据错误。
3. **原混合方案重点任务采样不足。**原先按 18 任务均衡、官方/本地各 50% 采样，两个重点任务的本地数据合计只占约 5.6%。现已按用户要求排除另外 16 任务的本地训练数据，新方案中两个本地任务合计占 50%；效果待实际训练与 rollout 验证。
4. **数据准备效率不足，已切换实现。**旧全量复核逐帧重新打开视频、定位解码，导致训练等待过长。现已停止旧复核，保留全部转换数据，改为每个视频文件打开一次并连续解码；全部画面、动作、来源哈希、时间戳和轨迹边界仍逐一检查。每 10 条轨迹输出进度和预计剩余时间。本轮只执行一次完整视频审计，其结果同时作为转换证明，随后执行真实混合 batch 预检。
